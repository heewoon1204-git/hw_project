# 쿠버네티스 리소스 구성하면서 발생한 문제

## 1. Helm으로 aws-load-balancer-controller 설치 중 pod CrashLoopBackOff 장애 발생

### 장애 현상

helm으로 aws-load-balancer-controller 설치했으나 CrashLoopBackOff 장애가 계속 발생하고 있는 상태

```bash
# 상태 확인
kubectl get pods -A | grep controller

# 결과
kube-system   aws-load-balancer-controller-6bf75b7bcb-g4zrl    0/1     CrashLoopBackOff   8 (3m4s ago)   
kube-system   aws-load-balancer-controller-6bf75b7bcb-ml8bm    0/1     CrashLoopBackOff   8 (3m28s ago)   
```

pod log를 살펴보면 "failed to get VPC ID" 상태

```bash
# 로그 확인
kubectl logs -n kube-system aws-load-balancer-controller-6bf75b7bcb-g4zrl

# 에러 로그 
{"level":"info","ts":"2026-08-12T01:55:31Z","msg":"version","GitVersion":"v3.5.0","GitCommit":"11eb202c97e4ae2ee45e0658c4cde9a4b59f33d4","BuildDate":"2026-08-03T22:03:44+0000"}

{"level":"error","ts":"2026-08-12T01:55:36Z","logger":"setup","msg":"unable to initialize AWS cloud","error":"failed to get VPC ID: failed to fetch VPC ID from instance metadata: error in fetching vpc id through ec2 metadata: get mac metadata: operation error ec2imds: GetMetadata, canceled, context deadline exceeded"}
```

### 장애 원인

helm 설치할 때 VPC ID를 지정하지 않았음. <br>
그래서 controller가 EC2 metadata를 통해 VPC 정보를 얻으려고 IMDS에 접근했는데 IMDS 접근이 안되가지고 timeout이 발생함. <br>
접근이 안됐던 이유는 전날 eks node를 내려놓고 controller 설차힐 때 다시 올려놓지 않았기 때문....

```bash
# helm 설치 시 사용한 스크립트
helm install aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=hw-infra-eks-cluster \             
  --set serviceAccount.create=false \               
  --set serviceAccount.name=aws-load-balancer-controller \. 
  --version 3.5.0
```

### 장애 해결

VPC ID를 추가해서 Upgrade해주면 정상젹으로 pod가 Running 됨.

```bash
helm upgrade aws-load-balancer-controller \
  eks/aws-load-balancer-controller \
  -n kube-system \
  --reuse-values \
  --set vpcId=vpc-0d20aba4f77bf1cc3
```

## 2. ALB Access log를 활성화하고 S3 주소를 넣었을 때 발생한 권한 에러

### 장애 현상

ALB Log를 쌓기 위해 Access log를 활성화고 S3 주소를 넣었는데 해당 에러가 발생

```bash
InvalidConfigurationRequestException: Access Denied for bucket: hw-project-alb-logs. Please check S3bucket permission
```

### 장애 원인

ALB가 해당 S3에 로그를 쓰려고 하는데 S3가 ALB 로그 전달서비스의 PutObject를 허용하지 않아서 장애 발생. <br>
S3 버킷 정책으로 로그 전달 서비스에 쓰기 권한을 줘야 문제가 생기지 않음.

### 장애 해결

ALB log를 저장할 S3의 Bucket policy를 추가하면 장애 해결

```bash
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "Service": "logdelivery.elasticloadbalancing.amazonaws.com"
      },
      "Action": "s3:PutObject",
      "Resource": "arn:aws:s3:::hw-project-alb-logs/AWSLogs/my_vpc_id/*"
    }
  ]
}
```
