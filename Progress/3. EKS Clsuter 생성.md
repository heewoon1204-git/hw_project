# EKS Clsuter

## EKS Cluster 생성

### 1. Cluster

ARC Zonal shift : 장애가 발생한 AZ를 의도적으로 트래픽 제외하는 설정
        -> 장애 대응 테스트 시 사용할 예정

Control plane scaling tier : 대규모/고트래픽 환경에서 컨트롤 플레인의 처리량을 높여야할 때 사용하는 옵션

Envelope encryption : 버네티스 시크릿 같은 데이터를 etcd에 저장할 때 추가로 암호화할지 결정
```bash
# Cluster configuration

Name : hw-infra-eks-cluster
Kubernetes version : 1.35
EKS Auto Mode : Disabled
Upgrade policy : Standard support
Cluster IAM role : hwEKSAutoClusterRole
Kubernetes cluster administrator : access
Allow cluster administrator access
Authentication mode : EKS API and ConfigMap
Control plane scaling tier : Standard

# ARC Zonal shift
ARC Zonal shift : Enabled

# Deletion protection
Deletion protection : Enabled
```

## EKS 접근

### EKS cluster 설정 추가

AWS CLI가 EKS 정보를 가져와서 접속하려는 PC의 "~/.kube/config"에 eks cluster 관련 설정을 추가

```bash
aws eks update-kubeconfig \
  --region ap-northeast-2 \
  --name hw-infra-eks-cluster \
  --profile hw-infra
```

### EKS endpoint 란?

EKS에는 쿠버네티스 API Server가 있고 kubectl은 여기에 요청을 보냄 <br>
이 API Server에 접근하기 위한 주소가 바로 EKS Cluster Endpoint임.

public, private 경로를 제공

```bash
kubectl
   │
   │ HTTPS 443
   ▼
EKS Kubernetes API Server
```

1. public endpoint

  인터넷을 통해서 외부에서 접속할 수 있는 경로

2. private endpoint

  ```bash
    VPC
  └─ Private Subnet
        │
        │ VPC 내부 네트워크
        ▼
  EKS Private Endpoint
        │
        ▼
  Kubernetes API Server
  ```

3. public and private 

  ```bash
                      EKS API Server
                         ▲
                         │
              ┌──────────┴──────────┐
              │                     │
          Public 경로             Private 경로
              │                     │
           인터넷                    VPC
              │                     │
          Mac IP/32                 Node
  ```
