## 환경 세팅

### 1. Python 가상환경에서 Flask 환경 만들기

현재 PC에서 가상환경 만든 후 Flask(웹 서버) 설치

-m venv : pyton의 venv 모듈 생성

```bash
# 가상환경 만들기
python3 -m venv .venv

# 활성화
source .venv/bin/activate
```

가상환경이 만들어졌으면 Flask(웹 서버) 설치

- boto3 : AWS S3 접근

```bash
# Flask 설치
pip install flask boto3

# requirements.txt 파일 생성하기
# 현재 파이썬 환경에 설치된 패키지들을 requirements.txt로 저장하는 명령어
# requirements.txt는 준비물 목록. 도커가 이거보고 Flask 필요 boto3 필요, gunicorn 필요.. 설치해야지!가 됨
pip freeze > requirements.txt
```

### 3. dockerfile 생성

```bash
# Dockerfile

FROM python:3.12-slim. -----> Python 3.12가 설치되어 있는 Linux 환경을 바탕으로 이 이미지를 만들어줘. 도커는 기존 이미지를 가져와서 그 위에 내가 필요한 환경을 쌓는 방식이기 때문에 python:3.12-slim 이미지를 가지고 오라는 뜻

WORKDIR /app       ---------> 도커 컨테이너 안에서 작업할 폴더를 /app으로 지정해줘.

COPY requirements.txt .   --> 내 컴퓨터에 있는 requirements.txt를 Docker 이미지의 현재 작업 폴더로 복사해줘.

RUN pip install --no-cache-dir -r requirements.txt  ----> RUN : 도커 컨테이너 안에서 실행할 명령어 

COPY app.py .          ---------> app.py 파이선 프로그램을 복사해줘
COPY templates ./templates  ----> templates 폴더를 복사해줘

EXPOSE 5001     ----------------> 이 컨테이너의 애플리케이션이 5001 포트를 사용한다고 도커에게 알려주는 설정
                                  여기까지는 도커가 이미지 만들 때까지의 설정

CMD ["gunicorn", "--bind", "0.0.0.0:5001", "app:app"]   ---> 컨테이너가 실행될 때 이 명령어를 실행
                                                             여기서부터는 이미지를 실행할 때 사용할 것

gunicorn : Flask 앱을 실행하기 위한 Python WSGI 서버
--bind 0.0.0.0:5001 : 컨테이너의 모든 네트워크 인터페이스에서 5001 포트를 받아라
app:app : app(app.py):app(Flask 객체)
```

### 4. docker로 이미지 생성

Dockerfile 파일이 있는 위치로 이동해서 진행하기

docker build : 도커 이미지 만드는 명령어 <br>
build -t alb-log-viewer:1.0 : 이미지 이름:태그<br>
. : 현재 폴더를 도커 빌드의 재료로 사용

```bash
# 명령어
docker build -t alb-log-viewer:1.0 .

# 확인
docker images

# 실행
docker run --rm -p 5001:5001 alb-log-viewer:1.0
```

### 5. docker 이미지를 AWS ECR에 올리기

1. ECR 레파지토리 생성하기

    AWS Console에서 ECR → Repositories → Create repository → alb-log-viewer 이름으로 생성

2. ECR에 docker 인증

    ```bash
    # 인증하기
    aws ecr get-login-password \
        --region ap-northeast-2 \
        --profile hw-infra \
        | docker login \
        --username AWS \
        --password-stdin \
        245067526307.dkr.ecr.ap-northeast-2.amazonaws.com

    # 성공 결과
    Login Succeeded
    ```

3. 이미지에 tag 추가하기

    ECR에 Push하려면 이미지 이름을 ECR 주소까지 포함하도록 tag를 추가해야함

    ```bash
    # tag 추가
    docker tag \
        alb-log-viewer:1.0 \
        245067526307.dkr.ecr.ap-northeast-2.amazonaws.com/alb-log-viewer:1.0

    # 확인
    docker images

    # 이미지가 1개 더 생긴게 아니라 두개가 같은 이미지를 가리킴. ECR로 보내기 위한 이름표를 하나 붙인것
    ```

4. ECR에 push 하기

5. Pod Identity 작업하기

    s3 = boto3.client("s3") 코드 실행할 때 S3에 접근할 AWS 권한이 필요함. <br>
    Pod Identity로 권한 작업을 하기 위해 먼저 ServiceAccount 생성

    ```bash
    # ServiceAccount 생성
    # alb-log-viewer-sa.yaml

    apiVersion: v1
    kind: ServiceAccount
    metadata:
    name: alb-log-viewer-sa
    namespace: monitoring
    ```

    ServiceAccount 생성했으면 IAM Role 생성하기

    ```bash
    Trusted entity type : Custom trust policy
    Custom trust policy :
            {
                "Version": "2012-10-17",
                "Statement": [
                    {
                    "Effect": "Allow",
                    "Principal": {
                        "Service": "pods.eks.amazonaws.com"
                    },
                    "Action": [
                        "sts:AssumeRole",
                        "sts:TagSession"
                    ]
                    }
                ]
            }
    Permissions policy :
            {
                "Version": "2012-10-17",
                "Statement": [
                    {
                    "Effect": "Allow",
                    "Action": "s3:ListBucket",
                    "Resource": "arn:aws:s3:::hw-project-alb-logs"
                    },
                    {
                    "Effect": "Allow",
                    "Action": "s3:GetObject",
                    "Resource": "arn:aws:s3:::hw-project-alb-logs/*"
                    }
                ]
            }
    ```

    IAM Role 생성이 완료됐으면 EKS Pod Identity로 연결하기

    AWS Console → EKS → 네 Cluster → Access → Pod Identity associations → Create

    ```bash
    IAM role : 위에서 생성했던 Role 선택
    Kubernetes namespace : monitoring
    Kubernetes service account : 위에서 생성했던 ServiceAccount
    ```

    생성이 잘 됐는지 확인해보기!

    ```bash
    aws eks list-pod-identity-associations \
        --cluster-name hw-infra-eks-cluster \
        --profile hw-infra \
        --region ap-northeast-2
    ```
