### 3. dockerfile 생성

```bash
# Dockerfile

FROM python:3.12-slim. -----> Python 3.12가 설치되어 있는 Linux 환경을 바탕으로 이 이미지를 만들어줘. 도커는 기존 이미지를 가져와서 그 위에 내가 필요한 환경을 쌓는 방식이기 때문에 python:3.12-slim 이미지를 가지고 오라는 뜻

WORKDIR /app       ---------> 도커 컨테이너 안에서 작업할 폴더를 /app으로 지정해줘.

COPY requirements.txt .   --> 내 컴퓨터에 있는 requirements.txt를 Docker 이미지의 현재 작업 폴더로 복사해줘.

RUN pip install --no-cache-dir -r requirements.txt  ----> RUN : 도커 컨테이너 안에서 실행할 명령어 

COPY app.py .          ---------> app.py 파이선 프로그램을 복사해줘
COPY templates ./templates  ----> templates 폴더를 복사해줘

EXPOSE 5001     ----------------> 이 컨테이너의 애플리케이션이 5001 포트를 사용한다고 도커에게 알려주는 설정
                                  여기까지는 도커가 이미지 만들 때까지의 설정

CMD ["gunicorn", "--bind", "0.0.0.0:5001", "app:app"]   ---> 컨테이너가 실행될 때 이 명령어를 실행
                                                             여기서부터는 이미지를 실행할 때 사용할 것

gunicorn : Flask 앱을 실행하기 위한 Python WSGI 서버
--bind 0.0.0.0:5001 : 컨테이너의 모든 네트워크 인터페이스에서 5001 포트를 받아라
app:app : app(app.py):app(Flask 객체)
```

### 6. EKS에 flask 앱 띄우기

1. . Pod Identity 작업하기

    s3 = boto3.client("s3") 코드 실행할 때 S3에 접근할 AWS 권한이 필요함. <br>
    Pod Identity로 권한 작업을 하기 위해 먼저 ServiceAccount 생성

    ```bash
    # ServiceAccount 생성
    # alb-log-viewer-sa.yaml

    apiVersion: v1
    kind: ServiceAccount
    metadata:
    name: alb-log-viewer-sa
    namespace: monitoring
    ```

    ServiceAccount 생성했으면 IAM Role 생성하기

    ```bash
    Trusted entity type : Custom trust policy
    Custom trust policy :
            {
                "Version": "2012-10-17",
                "Statement": [
                    {
                    "Effect": "Allow",
                    "Principal": {
                        "Service": "pods.eks.amazonaws.com"
                    },
                    "Action": [
                        "sts:AssumeRole",
                        "sts:TagSession"
                    ]
                    }
                ]
            }
    Permissions policy :
            {
                "Version": "2012-10-17",
                "Statement": [
                    {
                    "Effect": "Allow",
                    "Action": "s3:ListBucket",
                    "Resource": "arn:aws:s3:::hw-project-alb-logs"
                    },
                    {
                    "Effect": "Allow",
                    "Action": "s3:GetObject",
                    "Resource": "arn:aws:s3:::hw-project-alb-logs/*"
                    }
                ]
            }
    ```

    IAM Role 생성이 완료됐으면 EKS Pod Identity로 연결하기

    AWS Console → EKS → 네 Cluster → Access → Pod Identity associations → Create

    ```bash
    IAM role : 위에서 생성했던 Role 선택
    Kubernetes namespace : monitoring
    Kubernetes service account : 위에서 생성했던 ServiceAccount
    ```

    생성이 잘 됐는지 확인해보기!

    ```bash
    aws eks list-pod-identity-associations \
        --cluster-name hw-infra-eks-cluster \
        --profile hw-infra \
        --region ap-northeast-2
    ```

2. Deployment 만들기

    serviceAccountName : EKS Pod Identity가 이 ServiceAccount를 보고 alb-log-viewer-sa에 alb-log-viewer-s3-role을 연결해줌! <br>
    pod가 정상적으로 떴는지 확인하기

    ```bash
    apiVersion: apps/v1
    kind: Deployment
    metadata:
    name: alb-log-viewer
    namespace: monitoring
    spec:
    replicas: 1
    selector:
        matchLabels:
        app: alb-log-viewer
    template:
        metadata:
        labels:
            app: alb-log-viewer
        spec:
        serviceAccountName: alb-log-viewer-sa
        containers:
            - name: alb-log-viewer
            image: 245067526307.dkr.ecr.ap-northeast-2.amazonaws.com/alb-log-viewer
            ports:
                - containerPort: 5001
    ```

3. Service 만들기

    ```bash
    # yaml 생성
    apiVersion: v1
    kind: Service
    metadata:
    name: alb-log-viewer
    namespace: monitoring
    spec:
    selector:
        app: alb-log-viewer
    ports:
        - protocol: TCP
        port: 80        -------> Service : 80
        targetPort: 5001.  ----> pod : 5001
    type: ClusterIP

    # 적용
    kubectl apply -f alb-log-viewer-service.yaml

    # endpoint에 pod가 잘 저장됐는지 확인
    kubectl get endpoints -n monitoring alb-log-viewer

    # 결과
    NAME             ENDPOINTS         AGE
    alb-log-viewer   10.0.2.202:5001   24s
    ```
    
4. 기존 ALB에 연결하기

    기존 ALB는 application namespace에 있고, alb_viewer는 monitoring namespace에 있음. <br>
    -> 쿠버네티스 ingress는 다른 namespace의 service를 직접 backend로 지정할 수 없는 문제가 발생함..

    그래서 AWS Load Balancer Controller의 IngressGroup을 사용해서 서로 다른 namespace에서 같은 ALB를 공유하게 설정해야함

    ```bash
                            ┌── application Ingress
                            │       /
                            │       ↓
      heewoon1204.com → ALB ┤    nginx
                            │
                            └── monitoring Ingress
                                    /logs
                                    ↓
                            alb-log-viewer
    ```

    먼저 기존 ingress에 group 설정을 추가해야함

    ```bash
    # ingress.yaml에서 metadata annotations에 group 추가하기
    alb.ingress.kubernetes.io/group.name: heewoon1204
    ```

    그 다음 monitoring namespace에 새로운 Ingress 생성하기
    ```bash
    apiVersion: networking.k8s.io/v1
    kind: Ingress
    metadata:
    name: alb-log-viewer-ingress
    namespace: monitoring
    annotations:
        alb.ingress.kubernetes.io/group.name: heewoon1204
        alb.ingress.kubernetes.io/target-type: ip
    spec:
    ingressClassName: alb
    rules:
        - http:
            paths:
            - path: /logs
                pathType: Prefix
                backend:
                service:
                    name: alb-log-viewer
                    port:
                    number: 80
    ```

    수정 및 생성을 완료했으면 잘 적용됐는지 확인하기

    ```bash
    # 확인 
    kubectl get ingress -A

    # 결과
    # 두 Ingress의 ADDRESS가 같음
     NAMESPACE     NAME                     CLASS   HOSTS   ADDRESS                                                                 PORTS   AGE
    application   application-ingress      alb     *       k8s-heewoon1204-84896dc8ab-525480978.ap-northeast-2.elb.amazonaws.com   80      2d10h
    monitoring    alb-log-viewer-ingress   alb     *       k8s-heewoon1204-84896dc8ab-525480978.ap-northeast-2.elb.amazonaws.com   80      54s
    ```
